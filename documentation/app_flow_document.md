# App Flow Document for Codeguide Manufacturing App

## Onboarding and Sign-In/Sign-Up
A new user begins by navigating to the landing page, which welcomes factory staff and managers to the manufacturing starter application. The landing page presents a clear call to action for signing in or signing up. When a user chooses to create a new account, they are taken to the sign-up page. This page asks for an email address, a password, and basic profile information such as full name and role within the manufacturing environment. Once the user submits these details, the system uses secure session management to confirm the account and then redirects the user to a page prompting email verification. After verifying their email through a link, the user can sign in with their credentials. If a user forgets their password, they click a “Forgot Password” link on the sign-in page, enter their registered email, and receive a one-time reset link. That link opens a password reset form, where the user chooses a new password. Once the password reset is confirmed, they are redirected back to the sign-in page to access the application. Social login options can be added if desired, but by default the flows rely on email and password. Signing out is as simple as clicking the user avatar in the top header and choosing “Sign Out,” which ends the session and returns the user to the landing page.

## Main Dashboard or Home Page
After signing in, the user lands on the secure manufacturing dashboard. At the top is a header displaying the application name, a theme toggle switch for light or dark mode, and the user avatar with access to profile settings and sign-out. On the left side is a vertical navigation menu listing core areas such as Dashboard, Bill of Materials, Inventory Management, Production Planning, Work Orders, and Reports. The main content area shows a series of KPI widgets that present Overall Equipment Effectiveness, current inventory levels, and production plan adherence. Below these widgets, an interactive chart displays real-time production throughput against target values. From this main dashboard, the user can click on any KPI or navigation link to dive into specific modules.

## Detailed Feature Flows and Page Transitions
When the user selects the Bill of Materials section from the sidebar, they arrive at a page listing existing BOMs in a responsive data table. Each row links to a detailed BOM view. To create a new BOM, the user clicks the “New BOM” button in the top corner, filling out form fields for BOM code, description, and a dynamic list of material items with quantities. Saving the form sends a POST request to the `/api/bom` endpoint, which validates the data, writes it to the database, and then redirects back to the BOM list with a success confirmation. From the inventory module, the user sees a paginated list of inventory items, each showing SKU, available quantity, and location. Clicking an item opens an edit form where quantity adjustments or location updates can be made. Submitting changes issues a PUT request to `/api/inventory/[itemId]`, and on success the user returns to the inventory list.

In the Production Planning area, the user views a calendar or list of planning slots. Creating a production plan involves choosing a date range, selecting finished goods, and assigning required BOMs and quantities. Saving the plan triggers a secure API call to `/api/production/plan`, which creates the plan and schedules corresponding work orders. These work orders appear under the Work Orders section. On the work orders page, each entry shows status and scheduled date. Clicking a work order navigates to a detailed view where the user can issue material or record finished goods. When issuing material, a form lists required components and current stock levels. After the user confirms quantities, the client sends a POST request to `/api/production/work-order/[woId]/issue-material`. The server wraps inventory decrement and material issue record creation in a database transaction, returning an error if stock is insufficient. Once material is issued, the work order status updates. Later, to record finished goods, the user enters completed quantity on the same work order page and submits to `/api/production/work-order/[woId]/finish`, which updates inventory and marks the work order as complete. Throughout these flows, the sidebar and header remain visible, enabling quick jumps to other modules.

## Settings and Account Management
Accessing the user avatar in the header opens a dropdown menu with a link to Profile Settings. The Profile Settings page displays the user’s name, email, and role. Here the user can update their personal information, change their password, or configure notification preferences. Notification settings allow toggling email alerts for critical events such as low inventory warnings or production delays. All changes are saved via secure API calls to `/api/user/profile`. There are no billing or subscription pages in this starter kit, but additional billing flows can be integrated if needed. After updating settings, the user clicks a “Save and Return” button, which confirms success and returns them to the main dashboard.

## Error States and Alternate Paths
If users enter an incorrect password during sign-in, an inline error message appears under the input fields prompting them to retry or reset their password. During form submissions in modules like BOM creation or inventory updates, invalid data triggers inline validation errors that explain what needs fixing. If the user loses network connectivity, a banner appears at the top indicating offline status, and edits are temporarily disabled until connection is restored. In the production workflow, attempting to issue more material than available stock results in a clear error message returned from the server, displayed in a modal dialog. Server errors, such as a database failure, show a user-friendly fallback page with a retry button. Any 404 or unmatched route leads to a custom “Page Not Found” screen with navigation links back to the main dashboard.

## Conclusion and Overall App Journey
A typical user journey begins at the landing page, moves through a straightforward sign-up or sign-in process, and lands on a secure dashboard showing critical manufacturing metrics. From there, users visit module pages for Bill of Materials, Inventory Management, Production Planning, and Work Orders, each offering list views and detailed forms. Core actions like creating BOMs, adjusting inventory, scheduling production, issuing materials, and recording finished goods connect seamlessly via secure API routes and type-safe database transactions. Settings and profile management remain accessible through the header, and robust error handling guides users back on track if issues arise. This flow ensures that from account creation to daily manufacturing tasks, every step is clear, connected, and reliable.
